# ai slop helper

Помітки походження для HTML-документа. Біля кожного блока стоїть рейка з іконкою, яка
каже, звідки цей текст: перевірений факт із джерелом, судження автора — чи згенерований
асистентом абзац, якого ніхто не перевіряв. Плюс колонка зауважень збоку, щоб сказати,
що з блоком робити.

Потрібен лише Python 3.8+ зі стандартної поставки. Ні залежностей, ні збірки.

```bash
git clone https://github.com/ArtemZh/Ai_slop_helper.git
cd Ai_slop_helper
python3 prov_server.py 8743
```

Далі `http://127.0.0.1:8743/index.html` — демо-стаття, повністю розмічена. Клікайте по
іконках зліва, лишайте зауваження справа.

---

## Яку проблему це розв'язує

Документів стало багато. Аналітика, розбори, специфікації, довідки — і майже кожен
починається з чернетки, яку пише асистент. Писати він навчився швидко, і в цьому вся
проблема: **вузьким місцем стала не робота, а вичитка**.

Асистент пише однаково переконливо незалежно від того, звідки взяв матеріал. Абзац із
дослідження і абзац, який він щойно вигадав, виглядають абсолютно однаково: той самий
тон, та сама впевненість, ті самі рівні формулювання. Тому перед здачею документ
доводиться перечитувати цілком і по кожному твердженню згадувати, звідки воно взялося.
На третьому документі за тиждень це перестає працювати: пам'ять не тримає, а перевіряти
все заново дорожче, ніж написати.

Далі стається одне з двох. Або в документ проникає вигадане — цифра без джерела,
правдоподібне узагальнення, посилання на «дослідження», якого ніхто не бачив. Або автор
перестає довіряти чернетці взагалі й переписує все руками, і тоді асистент не заощадив
нічого.

Цей проєкт вибирає третій шлях: **зробити походження кожного блока видимим прямо в
документі**. Асистент, пишучи, одразу позначає, звідки взяв матеріал — і чесно зізнається,
де вигадав. Вичитка перетворюється з суцільного перечитування на роботу зі списком: видно,
що перевірене, а що ні, видно, скільки лишилося, і видно, коли роботу закінчено — коли
на сторінці не лишилося жодної помітки «ai slop».

Зауваження на полях замикають цикл: замість переказувати правки в чаті, ви лишаєте їх
там, де вони стосуються, а асистент забирає їх разом із помітками одним заходом.

## Шість типів

| Тип | Підпис | Що означає |
|---|---|---|
| `fact` | Перевірено | взято з відкритих джерел або надано власником; джерело в списку в кінці, у тексті — номер |
| `hyp` | Гіпотеза | висловлене припущення або тлумачення |
| `mine` | Мій висновок | судження **власника** з його досвіду: текст, який він дав сам |
| `todo` | Доробити | тут потрібна ще робота |
| `redo` | Переробити · ai slop | текст, який згенерував асистент і не підкріпив джерелом |
| `del` | Видалити | блок під зніс |

Перші три лишаються у зданій роботі, останні три — робочі й мають зникнути до здачі.
`del` нічого не видаляє сам, це лише мітка.

**`mine` — це не «висновок асистента».** Помітка належить власникові: нею позначається
текст, який він продиктував або сформулював сам, навіть якщо асистент його переписав.

**Слоп — це `redo`, а не `hyp`.** Гіпотеза — висловлене припущення, з яким можна
працювати. Слоп — матеріал, якого ще ніхто не перевіряв. У свіжозгенерованій статті
`redo` не виняток, а нормальний стан більшості блоків: прохід власника полягає в тому,
щоб звести цей тип до нуля.

**Що не позначається.** Заголовки, надзаголовки й підписи до схем: вони нічого не
стверджують, а рейка біля кожного рядка перетворює ліве поле на частокіл. Помітка стоїть
на твердженні — абзаці, картці, таблиці, схемі. Прозовий прогон із кількох абзаців —
один блок, а не абзац на рейку.

## Мова

Підписи типів живуть в одному місці — `assets/prov-i18n.js`. Підтримані українська,
російська та англійська; мова береться з атрибута `lang` у `<html>`, тож сторінка нічого
не налаштовує:

```html
<html lang="ru">   <!-- пульт і легенда стануть російськими -->
```

З коду доступні три виклики:

```js
PROV_I18N.label('redo')      // «Переделать · ai slop» для lang="ru"
PROV_I18N.icon('fact')       // svg іконки типу
PROV_I18N.legendHTML()       // легенда цілком, усі шість типів
```

Легенду більше не треба писати руками в кожному документі — саме звідти й брався розхід
підписів між пультом і сторінкою.

## Робочий цикл

1. Асистент пише текст і **сам виставляє початкові помітки** — за тим, як писав кожен
   блок: взяв із джерела `fact`, вигадав сам `redo`, дав власник `mine`.
2. Власник проходить сторінку: міняє помітки й лишає зауваження.
3. Каже «опрацюй зауваження».
4. Асистент читає зауваження **разом** із робочими помітками — це один набір вхідних
   даних, а не два — править текст і прибирає відпрацьоване.

## Як влаштовано

```
prov-map.json        ← єдине джерело правди
   ↓ prov_apply.py   переносить типи в розмітку: клас + іконка
<ваш сайт>/*.html    ← наслідок, руками тут правити не треба
   ↑ prov_server.py  віддає сайт і приймає POST /api/prov
   ↑ prov-edit.js    пульт: клік по іконці міняє тип
```

Напрямок один: JSON → HTML. Правка класу в розмітці руками буде затерта наступним
прогоном. Якщо блок перебудували і помітка злетіла — вона повернеться прогоном скрипта,
відновлювати вручну нічого не треба.

Чому саме так і на яких пастках уже витрачено час — [docs/DESIGN.md](docs/DESIGN.md).

## Зауваження до блоків

Друга колія поверх поміток. Помітка каже, **звідки** взято блок; зауваження каже, **що з
ним зробити**, і на відміну від типу `todo` в ньому є текст.

Праворуч від тексту йде окрема колонка. Біля кожного блока в ній постійно стоїть «+», а
вже залишене зауваження видно там же — весь час, без розкриття. Колонка з'являється
тільки разом із пультом: без нього верстка сторінки не змінюється, а на вузькому екрані
зауваження стають під блоком.

```bash
python3 comments.py          # усі зауваження разом із типом і початком тексту блока
python3 comments.py 03-2-1   # зауваження одного блока
```

Життєвий цикл короткий: відпрацьоване зауваження видаляється, історії немає. Натомість
перед видаленням асистент показує в переписці, що просили і що з кожним зроблено.

## Розмітка блока

```html
<div class="col mid" data-prov="03-1-1">…</div>
```

Достатньо атрибута `data-prov` — клас і іконку проставить `prov_apply.py`. Ключ довільний,
зручний формат `модуль-розділ-номер`. Для широких блоків (таблиця, сітка карток) додайте
`edge`: рейка піде в поле зліва й ширини блока не зачепить.

Запис у карті:

```json
"03-1-1": {
  "module": "03",
  "file": "index.html",
  "section": "Проблема",
  "block": "div",
  "text": "перші 110 символів — щоб упізнати блок, не відкриваючи сторінку",
  "type": "fact"
}
```

Змінюється в роботі одне поле — `type`. Решта переписується при перезбиранні карти.

## Команди

```bash
python3 prov_apply.py              # застосувати всю карту до розмітки
python3 prov_apply.py 03-2-1 todo  # змінити один блок і застосувати
python3 prov_server.py 8743        # локальний сервер із пультами
python3 comments.py                # список зауважень
```

`обновлено блоков: 0` — норма: розмітка вже збігається з картою.
У кожного скрипта є `--help`.

## Налаштування

| Змінна | Що задає | За замовчуванням |
|---|---|---|
| `PROV_SITE` | тека з розміченими HTML | `./site` |
| `PROV_MAP` | файл карти | `./prov-map.json` |
| `PROV_COMMENTS` | файл зауважень | `./comments.json` |

```bash
PROV_SITE=~/my-site PROV_MAP=~/my-site/prov-map.json python3 prov_server.py 8743
```

## Скіл для Claude Code

У теці `skill/` лежить готовий скіл: інструкція, за якою асистент сам виставляє помітки,
поки пише, і опрацьовує ваші зауваження на команду «опрацюй зауваження».

```bash
mkdir -p ~/.claude/skills
cp -r skill/ai-slop-helper ~/.claude/skills/
```

Перезапустіть сесію — далі скіл підхоплюється сам, коли ви просите написати документ.
Подробиці й варіант установки тільки для одного проєкту — у [skill/README.md](skill/README.md).

## Структура

```
prov_apply.py        карта → розмітка
prov_server.py       локальний сервер, API поміток і зауважень
comments.py          зауваження: сховище й вивід списком
prov-map.json        карта демо-сторінки
assets/              єдина копія того, що переносять до себе
  prov.css             стилі рейок, іконок і легенди
  prov-edit.js         пульт поміток
  comment-edit.js      пульт зауважень
  prov-map.html        службова сторінка: лічильники за типами і фільтр
site/                демо-стаття: index.html + base.css
skill/               скіл для Claude Code і як його поставити
docs/                DESIGN.md і вихідні іконки з поясненнями
```

Копій `assets/` у проєкті навмисно немає в двох місцях: друга копія «про запас» уже
одного разу розійшлася з першою. Сервер віддає цю теку за адресою `/assets/` незалежно
від того, який сайт ви розмічаєте.

## Підключення до свого сайта

1. Скопіюйте `assets/` поруч зі своїми сторінками (або лишіть там, де є — сервер
   віддасть її сам).
2. У кожній сторінці:

```html
<link rel="stylesheet" href="assets/prov.css">
<script src="assets/prov-edit.js"></script>
<script src="assets/comment-edit.js"></script>
```

3. Проставте `data-prov` на блоках, заведіть карту, запустіть `prov_apply.py`.

## Публічна збірка

Пульти самі вимикаються поза `127.0.0.1`, але з публічної збірки їх краще прибрати
разом із службовою сторінкою: `prov-edit.js`, `comment-edit.js`, `prov-map.html`.
Рейки й іконки лишаються видимими — вони читачеві й потрібні. Редагувати їх на
опублікованому сайті не можна, і це навмисно.
