# Скіл для Claude Code

`ai-slop-helper/SKILL.md` — інструкція, за якою асистент сам виставляє помітки під час
письма й опрацьовує ваші зауваження. Без нього механіка працює, але типи доводиться
пояснювати щоразу заново.

## Встановити

Для всіх проєктів — у домашню теку:

```bash
mkdir -p ~/.claude/skills
cp -r skill/ai-slop-helper ~/.claude/skills/
```

Тільки для одного проєкту — поруч із кодом:

```bash
mkdir -p .claude/skills
cp -r skill/ai-slop-helper .claude/skills/
```

Перезапустіть сесію. Перевірити, що скіл підхопився, можна командою `/ai-slop-helper` —
або просто попросивши написати документ: скіл має спрацювати сам, бо це прописано в його
`description`.

## Як це виглядає в роботі

**Ви:** «Напиши розбір трендів у проєктному менеджменті».

Асистент пише текст, розставляє `data-prov`, збирає карту, виставляє типи і піднімає
сервер. У відповідь ви отримуєте посилання і чесний розклад: скільки блоків перевірені,
скільки він вигадав сам.

**Ви** проходите сторінку: клік по іконці зліва міняє тип, «+» справа лишає зауваження.

**Ви:** «Опрацюй зауваження».

Асистент читає зауваження разом із помітками `todo`, `redo`, `del`, править текст,
показує перелік «що просили — що зроблено» і прибирає відпрацьоване.

## Що змінити під себе

У `SKILL.md` немає шляхів до конкретної теки: він спирається на змінні `PROV_SITE`,
`PROV_MAP`, `PROV_COMMENTS` і на те, що скрипти лежать у корені проєкту. Якщо у вас інша
розкладка — поправте розділ «Файли проєкту» в кінці файла.

Мова поміток у `SKILL.md` українська. Якщо документи ведете іншою — перекладіть підписи
в таблиці типів і у файлі `assets/prov-edit.js` (об'єкт `NAMES`).
